# Генератор отчётов по оценке компетенций

Веб-приложение на Python/Flask: вы загружаете протокол интервью в формате `.docx` или `.txt`,
при необходимости указываете целевую должность, а сервис формирует доказательный отчёт
по модели компетенций и заполняет им Word-шаблон `template.docx`.

Отчёт строится по трём этапам:

1. **Карта фактов** — из протокола извлекаются опыт, масштаб управления, ключевые цифры,
   примеры поведения, наблюдения интервьюера, противоречия и пробелы в данных.
2. **Черновик отчёта** — заключение, сильные стороны, риски и мотивация формулируются
   только по карте фактов и целевой должности.
3. **Редакторская проверка** — удаляются неподтверждённые утверждения, проверяются числа
   и контекст, согласуются заключение и пункты.

Готовая модель: `GigaChat-2-Pro`. Результат сохраняется в `output/` и скачивается из браузера.
Node.js и npm не используются.

## Состав проекта

| Файл | Назначение |
| --- | --- |
| `app.py` | Flask-приложение, извлечение текста, GigaChat API, три прохода, заполнение шаблона |
| `index.html` | Интерфейс загрузки протокола и указания целевой должности |
| `requirements.txt` | Python-зависимости |
| `template.docx` | Word-шаблон отчёта с тегами docxtpl |
| `competency_model.txt` | Детальная модель компетенций и индикаторы |
| `interview_guide.txt` | Вопросы гайда интервью и чек-лист |
| `example_report.txt` | Макет отчёта: ориентир стиля и структуры, не источник фактов |
| `certs/` | Корневой сертификат Минцифры для TLS-соединения с GigaChat |
| `output/` | Готовые `.docx`-файлы |
| `.env` | Локальный ключ GigaChat; не публикуется |

Макет `example_report.txt` не передаётся модели целиком: из него взяты только общие принципы
стиля, чтобы не перенести в отчёт факты, имена и выводы о другом кандидате.

## Установка

Нужен Python 3.10 или новее. Проверено на Python 3.12.

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка GigaChat

Приложение автоматически читает `.env` из папки проекта. Ключ хранится только локально.

```dotenv
GIGACHAT_AUTH_KEY=ваш_ключ_авторизации
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-2-Pro
```

`.env` исключён из git через `.gitignore` и не должен публиковаться. Переменная окружения
имеет приоритет над файлом:

```powershell
$env:GIGACHAT_AUTH_KEY = "новый_ключ"
```

Ключ можно указывать как есть или с префиксом `Basic ` — приложение нормализует значение.
Для физических лиц используется scope `GIGACHAT_API_PERS` (по умолчанию). Для юридических
лиц измените `GIGACHAT_SCOPE` на `GIGACHAT_API_CORP` или `GIGACHAT_API_B2B`.

### Сертификат Минцифры

GigaChat использует сертификат Минцифры, которого нет в стандартном хранилище Python.
В проекте уже есть `certs/russian_trusted_root_ca_pem.crt`. Если сертификат обновится,
скачайте новый с <https://www.gosuslugi.ru/crt> и замените файл либо укажите путь:

```powershell
$env:GIGACHAT_CA_BUNDLE = "C:\путь\к\russian_trusted_root_ca_pem.crt"
```

## Запуск

```powershell
python app.py
```

Откройте <http://localhost:5000>, выберите протокол `.docx`/`.txt`, при необходимости
укажите целевую должность и нажмите «Сгенерировать». После ответа GigaChat появится ссылка
на скачивание готового `.docx`.

## Публичная ссылка без прав администратора и без ngrok

Для доступа коллег используется `localtunnel` с закреплённым поддоменом. Аккаунт и права
администратора не нужны. Node.js уже установлен и используется только для туннеля; само
приложение остаётся на Python/Flask.

1. В `.env` задайте логин и пароль для входа:

   ```dotenv
   APP_USERNAME=team
   APP_PASSWORD=замените_на_длинный_пароль
   ```

   Если обе переменные заданы, приложение требует Basic Auth на всех страницах и скачивании.
   Если они пусты, приложение работает без пароля — это допустимо только локально.

2. Запустите `start_public.cmd` двойным щелчком. Скрипт:

   - запустит `app.py`, если приложение ещё не работает;
   - запустит туннель `localtunnel` и фоновый супервизор, который перезапускает его при обрыве;
   - запишет адрес в `public_url.txt` и покажет его в окне.

   Текущий адрес:

   ```text
   https://otchet-kompetencii-a50c.loca.lt
   ```

Ручной запуск туннеля:

```powershell
npx --yes localtunnel --port 5000 --local-host 127.0.0.1 --subdomain otchet-kompetencii-a50c
```

Поддомен закреплён, поэтому после перезапуска туннеля адрес не меняется. Если поддомен
занят, измените `--subdomain` в `run_tunnel.ps1` на другой и снова запустите
`start_public.cmd`.

Важно:

- компьютер должен быть включён и не уходить в сон; после пробуждения супервизор поднимет
  туннель с тем же адресом;
- трафик проходит через сторонний сервис `localtunnel`, поэтому не публикуйте там данные,
  которые нельзя передавать внешнему провайдеру;
- ссылка публичная, но закрыта паролем; не публикуйте её в открытых каналах;
- не пересылайте файл `.env` целиком: в нём также лежит ключ GigaChat. Показывайте коллегам
  только `APP_USERNAME` и `APP_PASSWORD`.

Посмотреть только логин и пароль:

```powershell
Select-String -Path .env -Pattern '^APP_USERNAME=|^APP_PASSWORD='
```

## Переменные окружения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `GIGACHAT_AUTH_KEY` | — | Ключ авторизации GigaChat (обязательно) |
| `GIGACHAT_SCOPE` | `GIGACHAT_API_PERS` | Версия API: `GIGACHAT_API_PERS`, `GIGACHAT_API_B2B`, `GIGACHAT_API_CORP` |
| `GIGACHAT_MODEL` | `GigaChat-2-Pro` | Модель GigaChat |
| `GIGACHAT_API_URL` | `https://api.giga.chat/v1/chat/completions` | Адрес метода генерации |
| `GIGACHAT_OAUTH_URL` | `https://ngw.devices.sberbank.ru:9443/api/v2/oauth` | Адрес получения токена |
| `GIGACHAT_CA_BUNDLE` | — | Путь к своему CA-сертификату (PEM) |
| `GIGACHAT_VERIFY_SSL` | `true` | `false` отключает проверку TLS (не рекомендуется) |
| `GIGACHAT_TIMEOUT` | `180` | Таймаут ответа GigaChat, секунды |
| `MAX_PROTOCOL_CHARS` | `120000` | Максимум символов протокола, передаваемых в модель |
| `REPORT_TWO_PASS` | `1` | `1` — сначала карта фактов, затем отчёт; `0` — сразу отчёт без карты фактов |
| `REPORT_VERIFY` | `1` | `1` — редакторская проверка отчёта; `0` — без отдельной проверки |
| `APP_USERNAME` | — | Логин Basic Auth для публичного доступа |
| `APP_PASSWORD` | — | Пароль Basic Auth; если логин и пароль заданы, доступ закрыт паролем |
| `HOST` | `127.0.0.1` | Интерфейс Flask |
| `PORT` | `5000` | Порт Flask |

Если карта фактов не построилась, приложение автоматически переходит к одноэтапной генерации,
чтобы не прерывать работу. Значение `REPORT_TWO_PASS=0` отключает первый этап принудительно.

## Шаблон отчёта

Шаблон заполняется библиотекой `docxtpl`, поэтому в Word-файле должны быть теги в двойных
фигурных скобках:

```
{{ fio }}
{{ current_role }}
{{ target_role }}
{{ birth_year }}
{{ diagnostic_date }}
{{ conclusion }}
{{ strengths }}
{{ risks }}
{{ motivation }}
```

`conclusion` — содержательное заключение по результатам оценки. `strengths`, `risks` и
`motivation` подставляются с переносами строк: каждый пункт начинается с `•`.
Текущий `template.docx` уже содержит все нужные теги, шрифты Times New Roman, заголовки
и колонтитул «КОНФИДЕНЦИАЛЬНО». При замене шаблона сохраните теги.

## Как это работает

1. `POST /generate` принимает файл из поля `file` (`.docx`/`.txt`, до 15 МБ) и
   необязательное поле `target_role`.
2. Для `.docx` текст извлекается через `mammoth`, при ошибке используется `python-docx`.
   Для `.txt` поддерживаются UTF-8 (в том числе с BOM) и CP1251.
3. Приложение получает OAuth-токен GigaChat, кэширует его и вызывает `chat/completions`
   с моделью `GigaChat-2-Pro`. Ответ запрашивается в виде JSON по схеме.
4. `extract_evidence()` выделяет карту фактов: опыт, масштаб, `key_numbers`, примеры
   поведения, наблюдения интервьюера, противоречия и пробелы. Имена и названия организаций
   заменяются ролями.
5. `write_report()` пишет отчёт по карте фактов, модели компетенций, гайду и целевой
   должности. Сырой протокол отдельно не передаётся, чтобы модель не добавляла детали,
   которых нет в карте.
6. `verify_report()` проверяет каждый пункт на факт-основание, исправляет числа и контекст,
   убирает домыслы и согласует заключение с пунктами.
7. Постобработка нормализует разметку, маркеры списков, год рождения, числа и контекст:
   например, 186 человек относятся к роте, 700 организаций — к базе лицензионного центра,
   100+ организаций — к административному центру, 9 лет — к работе в комитете;
   личные долги не превращаются в долги компании, длина колонн — в высоту.
   Если модель потеряла ключевой масштабный факт, он возвращается в блок сильных сторон;
   мотив сохранения здоровья возвращается в мотивацию, если он есть в протоколе.
8. Данные подставляются в `template.docx` через `docxtpl`, файл сохраняется в `output/`,
   клиент получает JSON со ссылкой `/download/<имя>.docx`.

Если GigaChat не поддерживает `response_format`, приложение автоматически повторяет запрос
без него и разбирает JSON из текста ответа.

## Правила отчёта

- Только факты из протокола. Не добавляются тесты, опросники, рекомендации, организации,
  имена, суммы и события, которых нет в материалах.
- Отсутствие данных не превращается в негатив: используются формулировки
  «в интервью не проверено», «требует проверки», «опыт ограничен примерами».
- Заключение — синтез, а не пересказ: степень соответствия целевой должности, 2–3 главных
  аргумента, ограничения и условия успешного назначения.
- Имена людей и названия организаций в отчёт не выводятся.
- Отчёт требует проверки экспертом: модель помогает структурировать факты, но не заменяет
  решение комиссии.

## API

`POST /generate` — `multipart/form-data`:

| Поле | Обязательно | Назначение |
| --- | --- | --- |
| `file` | да | Протокол `.docx` или `.txt` |
| `target_role` | нет | Целевая должность, до 200 символов |

Успешный ответ:

```json
{
  "ok": true,
  "filename": "report_20261026_110515_175d4f85.docx",
  "download_url": "/download/report_20261026_110515_175d4f85.docx",
  "data": {
    "fio": "Не указано",
    "current_role": "Начальник участка",
    "target_role": "Заместитель директора",
    "birth_year": "Не указано",
    "diagnostic_date": "Не указано",
    "conclusion": "...",
    "strengths": "• ...\n• ...",
    "risks": "• ...\n• ...",
    "motivation": "• ...\n• ..."
  }
}
```

Ошибка:

```json
{
  "ok": false,
  "error": "Текст ошибки"
}
```
